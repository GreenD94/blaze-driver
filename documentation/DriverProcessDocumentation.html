Flujo de Datos del Conductor

1. Autenticación y Verificación

El conductor se autentica y el sistema valida sus documentos y estado de aprobación.

2. Activación de Disponibilidad

El conductor activa su estado "en línea" y comienza a recibir solicitudes.

3. Recepción de Solicitudes

El sistema envía solicitudes de viaje cercanas al conductor.

4. Gestión del Viaje

El conductor acepta, navega y completa el viaje.

5. Cobro y Finalización

Se procesa el pago y se registra la ganancia del conductor.

✅ Proceso de Aceptación de Viaje

Flujo de Aceptación de Solicitud

1. Recepción de Notificación

El conductor recibe una notificación push con los detalles del viaje solicitado.

// Ejemplo de notificación MQTT recibida { "success_type": "new_ride_requested", "result": { "id": 12345, "rider_name": "Juan Pérez", "start_address": "Av. Principal 123", "end_address": "Centro Comercial Plaza", "proposed_fee": 25.50, "distance": 5.2, "estimated_time": 15 } }

2. Visualización de Detalles

El conductor ve los detalles completos del viaje en la interfaz.

Endpoint: GET /api/pending-ride-request

Obtiene lista de solicitudes pendientes cercanas

3. Evaluación y Decisión

El conductor evalúa la distancia, tarifa y decide aceptar o rechazar.

⚠️ Tiempo de Respuesta

El conductor tiene 60 segundos para aceptar la solicitud antes de que expire automáticamente.

4. Aceptación de la Solicitud

El conductor confirma la aceptación y se asigna al viaje.

Endpoint: POST /api/ride-request-respond

Envía respuesta de aceptación o rechazo

// Request de aceptación { "id": 12345, "driver_id": 789, "is_accept": "1", "proposed_fee": 25.50 }

📊 Métricas de Aceptación

  • Tiempo promedio de respuesta: 15-30 segundos
  • Porcentaje de aceptación: 85-90%
  • Radio de búsqueda: 5km
  • Filtros aplicados: Tipo de vehículo, calificación

🔧 Configuración del Conductor

  • Estado de disponibilidad: Online/Offline
  • Preferencias de viaje: Distancia máxima, tarifa mínima
  • Horarios de trabajo: Configurables
  • Zonas de servicio: Áreas preferidas

🧭 Navegación y Recogida

Proceso de Navegación al Origen

1. Confirmación de Aceptación

Una vez aceptada la solicitud, el sistema actualiza el estado del viaje.

ACCEPTED

2. Cálculo de Ruta

El sistema calcula la ruta óptima desde la ubicación actual del conductor hasta el origen del pasajero.

Endpoint: POST /api/update-user-status

Actualiza la ubicación del conductor en tiempo real

3. Navegación Activa

El conductor sigue la ruta proporcionada por Google Maps hacia el origen.

// Actualización de ubicación cada 12 segundos Map req = { "status": "active", "latitude": driverLocation.latitude.toString(), "longitude": driverLocation.longitude.toString(), }; await updateStatus(req);

4. Llegada al Origen

El conductor confirma su llegada al punto de origen.

Endpoint: POST /api/riderequest-update/{rideId}

Actualiza el estado del viaje a "ARRIVING"

// Request de llegada { "id": 12345, "status": "arriving" }

5. Confirmación de Llegada

El conductor confirma que ha llegado al punto exacto de recogida.

ARRIVED

🗺️ Características de Navegación

  • Proveedor de mapas: Google Maps
  • Actualización de ubicación: Cada 12 segundos
  • Precisión GPS: Alta precisión
  • Ruta optimizada: Tiempo más corto
  • Tráfico en tiempo real: Sí

⏱️ Tiempos de Espera

  • Tiempo de llegada estimado: Mostrado al pasajero
  • Tiempo de espera máximo: 5 minutos
  • Cobro por espera: Después de 2 minutos
  • Cancelación automática: Después de 5 minutos

🚗 Ejecución del Viaje

Proceso de Ejecución del Viaje

1. Verificación del Pasajero

El conductor verifica la identidad del pasajero mediante OTP o foto de perfil.

// Verificación OTP String otp = "1234"; // Código de 4 dígitos bool isValid = await verifyOTP(rideId, otp);

2. Inicio del Viaje

El conductor confirma que el pasajero está en el vehículo y inicia el viaje.

Endpoint: POST /api/riderequest-update/{rideId}

Actualiza el estado del viaje a "IN_PROGRESS"

// Request de inicio de viaje { "id": 12345, "status": "in_progress" }

3. Navegación al Destino

El conductor navega hacia el destino final del pasajero.

IN_PROGRESS

4. Tracking en Tiempo Real

El sistema rastrea la ubicación del vehículo durante todo el viaje.

📍 Tracking Continuo

La ubicación se actualiza cada 12 segundos y se comparte con el pasajero en tiempo real.

5. Llegada al Destino

El conductor llega al destino y confirma la finalización del viaje.

📱 Funcionalidades Durante el Viaje

  • Chat en tiempo real: Comunicación con el pasajero

  • Navegación: Google Maps integrado

  • Emergencias: Botón SOS

🔒 Seguridad Durante el Viaje

  • Verificación de identidad: OTP obligatorio

  • Compartir viaje: Con contactos de emergencia
  • Grabación de audio: Opcional

🏁 Finalización y Facturación

Proceso de Finalización del Viaje

1. Llegada al Destino

El conductor llega al destino final y confirma la llegada.

ARRIVED_AT_DESTINATION

2. Cálculo de Tarifa Final

El sistema calcula la tarifa final basada en distancia, tiempo y cargos adicionales.

Endpoint: POST /api/complete-riderequest

Finaliza el viaje y calcula la tarifa

// Request de finalización { "id": 12345, "service_id": 1, "end_latitude": -12.3456, "end_longitude": -78.9012, "end_address": "Destino Final", "distance": 5.2, "extra_charges": [], "extra_charges_amount": 0 }

3. Confirmación de Finalización

El conductor confirma que el viaje ha sido completado exitosamente.

COMPLETED

4. Generación de Recibo

El sistema genera un recibo detallado con todos los cargos.

// Estructura del recibo { "ride_id": 12345, "driver_name": "Carlos López", "rider_name": "Juan Pérez", "start_address": "Origen", "end_address": "Destino", "distance": 5.2, "duration": 15, "base_fare": 20.00, "distance_charge": 5.20, "time_charge": 3.75, "extra_charges": 0, "total_amount": 28.95 }

💰 Componentes de la Tarifa

  • Tarifa base: $20.00
  • Cargo por distancia: $1.00/km
  • Cargo por tiempo: $0.25/min
  • Cargos adicionales: Variables
  • Descuentos: Cupones aplicados

📊 Métricas de Finalización

  • Tiempo promedio de viaje: 15-20 minutos
  • Distancia promedio: 5-8 km
  • Tarifa promedio: $25-35
  • Porcentaje de completación: 95%

💳 Sistema de Cobro

Proceso de Cobro y Pago

1. Selección del Método de Pago

El conductor confirma el método de pago seleccionado por el pasajero.

// Métodos de pago disponibles enum PaymentMethod { cash, // Efectivo card, // Tarjeta de crédito/débito wallet, // Wallet interno online // Pago en línea }

2. Procesamiento del Pago

El sistema procesa el pago según el método seleccionado.

Endpoint: GET /api/current-riderequest

Obtiene detalles del viaje y estado del pago

3. Cobro en Efectivo

Si el pago es en efectivo, el conductor cobra directamente al pasajero.

💵 Cobro en Efectivo

El conductor debe cobrar la cantidad exacta y confirmar el cobro en la aplicación.

4. Procesamiento de Tarjeta

Para pagos con tarjeta, se procesa automáticamente a través de Stripe/Flutterwave.

// Procesamiento de tarjeta { "payment_type": "card", "amount": 28.95, "currency": "USD", "stripe_token": "tok_visa", "ride_id": 12345 }

5. Confirmación de Pago

El sistema confirma que el pago ha sido procesado exitosamente.

PAYMENT_PROCESSED

💳 Métodos de Pago Soportados

  • Efectivo: Cobro directo al pasajero
  • Tarjeta de crédito: Stripe/Flutterwave
  • Tarjeta de débito: Stripe/Flutterwave
  • Wallet interno: Saldo de la aplicación
  • Transferencia bancaria: Integración bancaria

💰 Gestión de Propinas

  • Propinas sugeridas: 10%, 15%, 20%
  • Propina personalizada: Monto libre
  • Propina en efectivo: Directa al conductor
  • Propina digital: Procesada por la app
  • Reporte de propinas: En el dashboard

✅ Ventajas del Sistema de Cobro

  • Múltiples opciones de pago para mayor flexibilidad
  • Procesamiento seguro con encriptación SSL
  • Confirmación automática de pagos
  • Reportes detallados de transacciones
  • Integración con sistemas contables

🚨 Gestión de Incidentes

Proceso de Gestión de Incidentes

Reporta incidentes o quejas

2. Botón de Emergencia (SOS)

El conductor puede activar el botón SOS en caso de emergencia.

Endpoint: POST /api/admin-sos-notify

Notifica emergencias al administrador

// Request de emergencia { "ride_id": 12345, "driver_id": 789, "emergency_type": "safety_concern", "location": { "latitude": -12.3456, "longitude": -78.9012 }, "description": "Situación de emergencia" }

El conductor puede cancelar el viaje por motivos válidos.

⚠️ Motivos de Cancelación Válidos

// Parámetros de búsqueda { "latitude": "-12.3456", "longitude": "-78.9012", "radius": 5000, // 5km "vehicle_type": "standard" }

// Estados posibles { "id": 12345, "status": "arriving" | "arrived" | "in_progress" | "completed" }
